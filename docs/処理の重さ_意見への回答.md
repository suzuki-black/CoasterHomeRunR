# 処理の重さ:「再反論への回答への意見」への回答(2026-10-06)

対象: 第三者のレビュー「処理の重さ:再反論への回答への意見」。5 章で求められた数字を測った。条件はこれまでと同じ(版 fa187bc)。

## 1. 事実の確認

- **長方形は、すでに列ごとに縦に塗っている**(gfx.s の rect_fill。1 列 = 横 2 ブロックを上から `ld (hl), n / inc l` で、
  帯をまたぐときだけ番地を付け直す。色は命令の即値に書き込む。左右の端の列だけニブルを合成)。
- **多角形の行も、提案の形になっている**(raster.s の fill。行ごとに左右を決め、ページ 0 に置いた
  `ld (hl), a / add hl, bc`(+8)× 32 の展開の途中へ飛ぶ。奇数の端は半バイトを合成)。
- **転送の区間は、VRAM で隣り合う変わった組をまとめたもの**(ステージ 3 で変わった 78 組が 19 区間。1 区間平均約 4 組)。
- 描画バッファの並びは提案の理解どおり(1 帯 = 8 行 × 64 ブロック = 256 バイト。帯の中で縦は連続、横は 8 バイトおき)。

  終わりの行の比較(f_end)と飛び先の書き換え(FILLJP)の 2 つで、ここは減らせる(見込み 0.4ms 程度)。

### 2.3 転送: 隣り合う組

1 章のとおり、変わった組は VRAM で隣り合うものを 1 区間にまとめている(ステージ 1: 39 組が 10.5 区間、ステージ 3: 78 組が 19 区間)。

### 2.4 飾りの点の中身

| 関数 | 1 回にすること | 1 回あたり |
|---|---|---|
| `_rpt_a` | リングの中心の投影と q(= 2^23 / z、ring_c)を引き(直前と同じリングなら引かない)、`中心 + (u, v) × q` を掛け算 2 回(PSCALE)で求めて `scr[i]` に置く。3D の変換も投影もしない | 約 270 サイクル |
| `_rquad_a` | 同じ形で u0・u1・v0・v1 の掛け算 4 回 → 行・列に丸めて画面に収める → rect_fill(塗りは別に数える) | 約 560 サイクル |

飾りはすでに「リングの中心の投影 1 点と拡大率」で 2D で求めている(提案の形)。前回の文書の「1 点あたり 500〜900 サイクル」は、
2 つの関数の時間を点の数だけで割った見積もりで、長方形の丸め・クリップ・塗りへの受け渡しを含んでいた。

### 2.5 割り込みを止めたときの遅れ

垂直帰線の割り込みが入るまでの遅れ(周期 16.688ms に対する、各回の入りのずれ。フレーム 600〜900):

| | 中央値 | 95% 点 | 最大 |
|---|---|---|---|
| ステージ 1 | 0.00ms | 0.08ms | 2.10ms |
| ステージ 3 | 0.00ms | 0.09ms | 2.45ms |

最大は、転送の前に比べる処理(割り込みを止めて SP を描画バッファに向ける)の分。R800 で送りながら比べる形にすると、止める時間は
転送全体(3〜7ms)に延び、音の 1 ティックの中で鳴り出しが最大 7ms ほど遅れることがある(ティックは失われず、テンポは崩れない)。
聞いて分かるかは耳で確かめる必要があり、作る人が判断すること。

## 3. 進め方

意見の 4 章の順に賛成する。確かめ方の基準と、ステージごとの目標(3 章)は、作る人が決める。基準を変えずにできるものから進める:
塗りの行ごとのメモリの読み書き → 手前で切る処理の割り算を辺ごとに覚える → 敵の対応表 → 転送を R800 で送る試作(割り込みの遅れの判断のあと)。

## 4. 追記: 「意見への回答への回答」を受けて(2026-10-06)

- 割り込み処理は VDP の状態を毎回読み(`in a, (0x99)`)、表示を切り替えるフレームだけ R#4 とスプライトの表を書く。転送は「前の切り替えが済んでから」
  始めるので、転送中に書くことはない。状態を読むとレジスタ書き込みの 2 バイトの組の途中がリセットされるので、番地の設定の 2 回の OUT の間だけ割り込みを止める。
- トンネルの帯の行(ステージ 3、フレーム 300〜500): 塗る行 293 のうち 254 行がトンネルの帯。同じ帯の別の面と同じ行に並ぶ行は 232(行 × 面)。
  ステージ 1 は 122 行のうち帯が 67、並ぶ行が 32。
- R800 で送りながら比べる案は試作したが、今の形より遅かった(docs/検証記録.md「R800 のまま、OUT の待ちの間に比べながら送る」)。
  openMSX の S1990 の待ちに隠せるのは、OUT の間の処理が 20〜30 サイクルまでで、「55〜60 サイクルが自由に使える」は当たらなかった。
