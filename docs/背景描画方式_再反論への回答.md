# 「背景描画方式への再反論」への回答 — 転送タイミングの検証結果

再反論（作り置き案を取り下げ、転送タイミングの変更を最優先にする提案）について、依頼された 4 項目を計測した。
結論から言うと、**ターボR では垂直帰線中も画面オフ中も VDP への書き込みは速くならない**（少なくとも openMSX では）。
転送時間の短縮は「いつ送るか」ではなく「何バイト送るか」でしか得られない。

## 1. 計測の方法

計測用 ROM `make vdpbench`（src/engine/vdpbench.c）を作った。

- VRAM の空き（0x3000〜）へ `OTIR` で 256 バイト書き、ターボR のシステムタイマ（E6h、3.911µs/カウント）で時間を測る
- 垂直帰線は VDP の S#2 の VR ビットで判定する
- 計測中は割り込みを止める
- 結果は画面に出すので、openMSX・WebMSX・実機のどれでも同じ ROM で測れる

openMSX の 2 機種で測った。

- TH_turboR_dev（C-BIOS を turbo R のハードで動かす開発用機種）
- My_FS-A1ST_512K（実機の FS-A1ST からダンプした BIOS）

## 2. 結果（2 機種とも同じ）

| 依頼 | 条件 | 1 バイトあたり | 表示中との比 |
|---|---|---|---|
| 1 | 表示中 | **8.67µs**（R800 で約 62 サイクル） | — |
| 1 | 垂直帰線中 | **8.67µs** | 変わらない |
| 2 | 画面オフ（R#1 の BL = 0） | **8.67〜8.69µs** | 変わらない |

| 依頼 | 垂直帰線の長さ | その間に書けるバイト数（8.67µs/B） |
|---|---|---|
| 3 | 60Hz: **4,376µs**（約 68 ライン） | **約 504 バイト** |
| 3 | 50Hz: **6,110µs**（約 96 ライン） | **約 704 バイト** |

## 3. 解釈

- 約 62 サイクルの待ちは VDP（V9958）の表示期間の制約ではない。**ターボR の S1990 が、R800 から VDP のポート（98h〜9Bh）への
  アクセスに一律に入れる待ち**と考えられる。表示中か、帰線中か、画面オフかに関係なく同じ値だった。
- 再反論 3 章の「帰線中は約 2µs まで縮む」は、V9938 単体（Z80 や VDP コマンドから見た値）の資料値で、ターボR の R800 からのアクセスには
  当てはまらない（openMSX での結果）。
- そのため、再反論 4 章の「転送だけで 10ms 以上削れる」という見込みは成り立たない。

| 条件 | 転送量 | 時間（実測値 8.67µs/B から） |
|---|---|---|
| 現状: 全画面 | 1536B | 13.3ms |
| HUD 13 行を除外（タイミングは問わない） | 1120B | **9.7ms**（3.6ms 短縮） |
| HUD 除外 + 帰線中 | 1120B | 9.7ms（帰線中でも同じ） |
| 全画面 + 50Hz | 1536B | 13.3ms（フレームの予算は 40ms に伸びるが、転送は縮まない） |

## 4. 再反論から採り入れる点

計測で否定されたのは「帰線中なら速い」の部分だけで、次の点は有効なので採り入れる。

| 打ち手 | 効果 | 備考 |
|---|---|---|
| HUD（下 13 行: 乗り物の縁とゲージ）を毎フレーム送らない | 転送 13.3 → 9.7ms（-3.6ms） | ネームテーブルの組み替えが必要。ゲージや宝の山が変わったときだけ送る |
| 50Hz の検討 | 予算 33.3 → 40ms（25fps 相当で頭打ち） | 転送は縮まないので、体感の滑らかさとの相談。いまの 13〜17fps なら 50Hz にしても上限には当たらない |
| 自前の割り込み処理 | — | 実施済み（ページ0の 0x0038 に自前の処理。BIOS を通らない） |
| パターンテーブルの 2 面切り替え | — | 実施済み（R#4 で切り替え） |

## 5. 優先順位（改めて）

転送は「何バイト送るか」でしか縮まないので、HUD の除外は 1 番目ではなく、描画側の打ち手と同列の 3.6ms になる。

| 順位 | 打ち手 | 見込み |
|---|---|---|
| 1 | 帯の管理の作り直しの続き | 7.1 → 4〜5ms |
| 2 | HUD 13 行を転送しない（ネームテーブルの組み替え） | 転送 -3.6ms |
| 3 | 変換・投影の C の部分をアセンブラへ | 約 3ms |
| 4 | 飾りの描き分け、描画距離の調整 | 面数枚分 |
| — | 遠い区間の断面近似 | 実施済み |

## 6. 残る確認

openMSX はターボR の VDP アクセスの待ちを機種の仕組みとして再現しているが、実機の値ではない。
来週届く実機の ROM カートリッジと WebMSX で、同じ `make vdpbench` の ROM を動かして確認する。

- ROM: `build/vdpb/TrolleyHomeRun_VDPBENCH [ASCII8].rom`
- 画面の見方:
  - DISP / VBL / OFF: 1 バイトの時間（0.01µs 単位。867 = 8.67µs）
  - V60 / V50: 垂直帰線の長さ（µs）と、その間に書ける見込みのバイト数
- 実機で VBL や OFF が DISP より明らかに小さければ、再反論の 3 章が実機では成り立つことになる。その場合は「帰線中に N バイト、残りは表示中」の
  分割転送（再反論 5 章の 4）を検討する。
