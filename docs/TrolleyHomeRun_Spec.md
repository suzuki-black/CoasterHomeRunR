# TrolleyHomeRun 試作版 開発指示書

MSX turbo R 専用 / SCREEN 3（マルチカラーモード）/ ROMカートリッジ / R800 DRAMモード

---

## 0. この指示書について

- 本書は短い試作版（プロトタイプ）を作るための指示書である。
- 「【要検証】」と書かれた項目は、実機または openMSX（turbo R 機種設定）で必ず動作確認してから確定すること。
- 仕様として定義はするが試作版では簡略化する項目は「【試作版では簡略化】」と明記する。

## 1. ゲーム概要

| 項目 | 内容 |
|---|---|
| ジャンル | 3D レールシューター（ガンシューティング型） |
| 仮タイトル | TROLLEY HOME RUN |
| 対象機種 | MSX turbo R（FS-A1ST / FS-A1GT） |
| 画面 | SCREEN 3（64×48 ブロック・16色）＋拡大スプライト |
| 音源 | PSG のみ（BGM・SE とも） |
| 媒体 | MegaROM カートリッジ（ASCII8 マッパー、128KB 想定） |

### あらすじ

洞窟の奥で宝物を見つけた瞬間、亜人たちが襲いかかってくる。主人公は宝をトロッコに積んで飛び乗り、ライフル1丁で応戦しながら脱出する。坑道の先は大きな地底湖、なぜかトロッコごと筏に乗って渡り、洞窟を出ると森のレール、そして町中のレール……なぜかレールは自宅の前まで続いていた。家に着いたとき、トロッコに残っていた宝の量で、主人公がどれだけお金持ちになれたかが決まる。

> 類似作品との差別化（2026-09-28 決定）: トロッコで宝を持って逃げる筋はセガ『レールチェイス』『レールチェイス2』と重なりが大きいため、
> 次の方針で見せ場と表現を独自のものにした。
> - ライフは「トロッコに積んだ宝の量」。被弾で金貨が飛び散って宝の山が減る（トロッコが壊れていく表現と「CAUTION」表示はやめた）。
>   回復は金貨袋。エンディングは持ち帰った宝の量で 3 通り。
> - 崖から落ちて川を走る・滝から落ちる・崖からダイブして別のレールに着地、はやめ、地底湖を筏で渡る場面にした。
> - 暴走汽車（鉄道兵器が追ってくる）はやめ、獣人たちが引く祭りの山車にした。
> - 振り向きの警告は文字（ENEMY BEHIND!）ではなく、画面左右の赤い下向き矢印と警告音にした。
> - ルート分岐は入れない（原作の看板の仕組みのため）。振り向きは強制イベントではなくプレイヤーの操作（B ボタン）のまま。

## 2. 操作仕様

| 操作 | 入力 | 備考 |
|---|---|---|
| 照準（スコープ）移動 | カーソルキー / ジョイスティック（ポート1）の8方向 | BIOS `GTSTCK`（A=0：カーソル、A=1：ポート1） |
| 射撃 | スペース / ジョイスティック A ボタン | BIOS `GTTRIG`（A=0：スペース、A=1：ポート1 A）。押しっぱなしで連射 |
| 前後切り替え（振り向き） | キーボードの B ボタン相当キー / ジョイスティック B ボタン | BIOS `GTTRIG`（A=3：ポート1 B）。キーボード側は `SNSMAT` でキーマトリクスを読む |
| ゲーム開始 | スペース / ジョイスティック A ボタン | タイトル画面 |

- カーソルキー・ジョイスティックは**照準移動専用**で、振り向きには使わない。
- 振り向きは B ボタンで**トグル**（前 ⇔ 後ろ）する。押した瞬間（立ち上がり）のみ受け付け、押しっぱなしで連続回転しない。
- 振り向きは即時切り替えではなく、約0.25秒（8フレーム@30fps）で180度回転する演出を入れる。回転中は射撃不可・B ボタン入力は無視。
- 照準の移動速度：2ピクセル/ティック（60Hz）。同じ方向を8ティック以上押し続けたら4ピクセル/ティックに加速。【要調整】
- 照準は画面内（ゲーム画面の領域）でクリップする。振り向き後も照準位置は保持する。
- トロッコの移動・速度はプレイヤーが操作できない。
- 連射間隔：6ティック（60Hz基準で毎秒10発）。弾数制限・リロードは試作版ではなし。

> 【要確認】キーボードの B ボタン相当キーをどのキーに割り当てるか（案：M キー＝キーマトリクス行4・ビット2、または GRAPH キー）。
>
> マウス操作は試作版では実装しない（「11. 未決事項・TODO」参照）。

## 3. ゲームルール

### 3.1 ライフ

- ライフ最大値：8。画面最下部にゲージ表示。
- 画面下部にトロッコの縁（前向きなら前の縁、後ろ向きなら後ろの縁）を常に表示する。自機（主人公）や手は描かない。
- ライフ = トロッコの縁の上に積んだ宝の山（金貨・宝石）。ライフが 1 減るごとに山が外側・上から低く細くなり、被弾の瞬間に金貨が飛び散る。
  ゲージは金色。トロッコの縁そのものは壊れない。宝の山に隠れた場所も撃てない。
- 被弾時はトロッコを一瞬揺らす。トロッコの縁に隠れた場所は撃てない。
- 敵の直接攻撃・敵弾の被弾・山車の体当たりで、それぞれ1ダメージ。
- ライフ0でゲームオーバー → 「GAME OVER」「NO TREASURE LEFT」表示 → タイトルへ戻る。
- 被弾時は画面全体を1フレーム赤くフラッシュ（パレット操作で実現）。

### 3.2 攻撃と当たり判定

- 射撃はヒットスキャン（撃った瞬間に判定）。
- 照準位置（ピクセル座標）を4で割ったブロック座標で判定する。
- 照準位置に重なる対象のうち、最も手前（Zが小さい）のものに命中。
- 命中時の演出：
  - 命中位置にヒットマーク（スプライト）を4フレーム表示。
  - 命中した敵を2フレームだけ白（パレット番号2）で描画してフラッシュ。
- 撃てる対象：敵本体、敵弾（矢・魔法弾）、金貨袋。

### 3.3 弱点システム

- 敵データは部位（頭・胴・脚）ごとの当たり領域とダメージ倍率を持つ構造にしておく。
- 【試作版では簡略化】全部位とも倍率1.0（全身が弱点）。

### 3.4 金貨袋（回復。実装内部の名前は MEDKIT のまま）

- レール沿いに配置（地底湖では水に浮いた木箱の上）。撃つとライフ（積んだ宝）が2増える（最大値を超えない）。
- 耐久度1。取り逃しても（画面外へ流れても）ペナルティなし。
- 茶色の袋に黄色の金貨で表現。

### 3.5 前後の襲撃と警告表示

- 敵が前後同時に襲ってくることは基本的にない。
- ステージスクリプトで区間ごとに「襲撃方向」（前 / 後ろ / なし）を指定する。
- 襲撃方向がプレイヤーの向きと逆のとき（前を向いていて後ろから、または後ろを向いていて前から）、画面の左右に
  赤い下向きの矢印（＝いま見ている向きの反対側から来る）を点滅表示し、警告音を鳴らす。文字の警告は出さない。
- 点滅周期：15フレーム点灯 / 15フレーム消灯。プレイヤーが正しい方向を向いたら即消去。

## 4. 敵仕様

### 4.1 共通

- 敵はすべて亜人（動物っぽい人間）。低解像度で形が判別しにくいため、**種族は色で区別する**。
- 敵の表示は「カメラ正対の矩形の集まり」（後述 7.4）で描く。3D座標で移動し、投影して拡大縮小される。
- 敵の状態：待機 → 出現 → 接近 / 射撃 → 攻撃 → （撃破 or 通過）
- トロッコが通り過ぎてカメラ後方に抜けた敵は消去する（追跡型は除く）。

### 4.2 雑魚キャラ

| ID | 名前 | 色（パレット） | 耐久 | 攻撃方法 | 特徴 |
|---|---|---|---|---|---|
| E01 | 猿人（斧） | 茶（4） | 1 | 近接・斧 | 最弱。レール脇から飛び出して接近 |
| E02 | コウモリ人 | 紫（5） | 2 | 近接・爪 | 飛行。後方から追跡してくる型あり |
| E03 | キリン人（槍） | 黄（6） | 3 | 近接・槍 | 首が長いシルエット。リーチが長く、少し遠い距離から攻撃 |
| E04 | 弓兵（猿人系） | 橙（7） | 2 | 矢 | 高台（Y座標が高い位置）から矢を撃つ |
| E05 | 魔法使い（コウモリ人系） | 水色（8） | 3 | 魔法弾 | 魔法弾は大きく遅い |

### 4.3 攻撃の仕様

- **近接攻撃**：カメラからの距離が攻撃距離（E01/E02：約2m、E03：約3.5m）に入ると、攻撃予備動作（0.5秒、敵が1回点滅）の後に1ダメージ。以後、2秒ごとに攻撃を繰り返す。倒すかトロッコが通過するまで続く。
- **矢（E04）**：3D空間をカメラに向かって直進。耐久1、撃ち落とし可。表示は橙の1×1ブロック（近いと2×2）。
- **魔法弾（E05）**：カメラに向かって低速で直進。耐久2、撃ち落とし可。表示は赤の2×2ブロック（近いと3×3）。
- 敵弾がカメラ手前の判定面（Z＜ニアクリップ）に達したら1ダメージ。

## 5. ステージ構成（試作版1周）

| # | 区間 | 目安時間 | トロッコ速度 | 襲撃方向 | 内容 |
|---|---|---|---|---|---|

| 1 | 洞窟 | 0:04〜1:00 | 遅→中 | 前→後→前 | E01中心、中盤にE02が後方から追跡。中ボスB01、終盤に大ボスB05（洞窟の主） |

| 5 | 森 | 1:58〜3:00 | 中 | 前→後→前 | 木の間にE03・E05。金貨袋2個。終盤にB02 |

| 8 | エンディング | — | — | — | 下記参照 |

> 実装メモ（試作版）: ROM 上は 5 ステージに分けた。ステージ 1 = #0〜1（洞窟）、ステージ 2 = #2（地底湖）、
> ステージ 3 = #5（森）、ステージ 4 = #6（町）、ステージ 5 = #7（自宅前）→ エンディング。ライフとスコアはステージをまたいで持ち越す。
> ステージの始めに名前（`STAGE 2 / THE RIVER` など）を約 1.5 秒出す。
> ステージ 2 は坑道から走りながら始まり、地底湖（「A LAKE?!」）でレールが途切れて筏に乗り（「ON A RAFT?!」）、向こう岸（「LAND HO!」）で
> レールに戻って洞窟を出る。湖に入る・岸に着くなど地形に結びついた演出は、時刻ではなくレール上の位置で起こす（7.7 の EV_AT）。
> 町: なぜか道にレールが敷いてあり（「WHY RAILS HERE?」）、両側は家並み（壁・屋根、家と家の間は空く、手前に妻壁と窓）。
> 祭りの山車（B03）は後ろから来る。自宅前: 道の突き当たりに自宅（桃色の壁・煙突・玄関）。亜人の王（B04）を倒すと
> 自宅の前まで走ってゆっくり止まり（「HOME SWEET HOME!」）、エンディングへ。

### 5.1 各ステージの見た目（パレット9〜15をステージごとに切り替え）

| ステージ | 環境ポリゴン | 色味 |
|---|---|---|
| 洞窟 | 断面が六角形のトンネル（壁・天井・床）、木の枠 | 暗い茶・灰・黒 |
| 地底湖 | 大きな空洞の水面・岩壁の岩棚・鍾乳石・水面の岩（奥は闇） | 暗い灰・青緑 |
| 森 | 木の幹（縦長の四角）・地面・葉の塊 | 濃い緑・緑・茶 |
| 町 | 家（箱型）・屋根（三角）・道 | 灰・赤茶・白・空色 |
| 自宅前 | 自宅（他の家より大きめ・目立つ色）・庭 | 町と同じ＋自宅の強調色 |

- 背景（地平線より上の空・下の地面）は、描画バッファのクリア時に行単位で2色塗り分けて表現する（ポリゴン処理不要で軽い）。

### 5.2 エンディング

- SCREEN 1 に切り替え、BIOS フォント（ひらがな使用可）で表示する。
- 表示例：
  ```
  たからものを もちかえった
  しゅじんこうは
  おおがねもちに なりましたとさ。          ← 持ち帰った宝（残りライフ）6 以上
  そこそこ かねもちに なりましたとさ。      ← 3〜5
  けっきょく びんぼうな ままでしたとさ。    ← 1〜2

        おしまい
  ```
- 残りライフ×1000点のボーナスをスコアに加算して最終スコアを表示。
- 数秒後、またはボタンでタイトルへ戻る。

> 実装メモ: 最後のステージのデータ（エンディングの間も読み込んだまま）に文（MSX の文字コード）と BGM を置く。
> SCREEN 1 は VDP のレジスタを直接設定し、フォントは BIOS の CGTABL から一時的にページ0を BIOS に戻して写す
> （開発用の C-BIOS のフォントでもひらがなが出ることを確認した。実機の BIOS のフォントでの見た目は WebMSX・実機で確かめる）。
> 約 8 秒後（1 秒過ぎたら A でも）タイトルへ戻り、SCREEN 3 を作り直す。

### 5.3 スコア（試作版は最小限）

- 雑魚：耐久×100点、ボス：耐久×200点、敵弾撃墜：50点、金貨袋：0点。
- スコアはブロックフォントで画面右上に小さく表示（数字のみ3×5ブロック）。表示負荷が気になる場合は試作版では省略し、エンディングでのみ表示してよい。

- スプライトモード1（SCREEN 3 の仕様）、**16×16・拡大モード**（R#1 のビット0とビット1を立てる）。画面上は32×32ピクセル。

| 番号 | 用途 | 色 |
|---|---|---|
| 0 | 照準 | 白 |
| 1〜3 | ヒットマーク | 白 or 黄 |

## 7. 技術仕様

### 7.1 CPU モードと起動

- 起動直後に BIOS `CHGCPU`（0180h）で R800 DRAM モードに切り替える。
  ```asm
      ld   a,82h        ; ビット0-1=2（R800 DRAMモード）、ビット7=1（ターボLEDも切替）
      call 0180h        ; CHGCPU
  ```
- 現在のモードは BIOS `GETCPU`（0183h）で確認できる。
- turbo R 以外の機種では起動しない（MSXバージョン番号を確認し、非対応ならメッセージを出して停止）。

> 【要検証】DRAM モードでは内蔵 RAM の一部（上位64KB相当）が BIOS のコピーに使われるため、その範囲のマッパーセグメントは使用禁止とする。使用可能なセグメント範囲を起動時に確認すること。

### 7.2 なぜ RAM にコードをコピーするか

- R800 はカートリッジスロット（外部スロット）へのアクセス時にウェイトが入り、ROM 上でコードを実行すると本来の速度が出ない。
- そのため、**ROM 上で実行するのは起動処理とローダーのみ**とし、ゲーム中に動くコードはすべて内蔵 RAM にコピーしてから実行する。

### 7.3 メモリ構成

#### ROM（ASCII8 マッパー、8KB バンク ×16 ＝ 128KB 想定）

- バンク切替レジスタ（8KB 窓ごと）：

| レジスタ | 切替対象の窓 |
|---|---|
| 6000h | 4000h〜5FFFh |
| 6800h | 6000h〜7FFFh |
| 7000h | 8000h〜9FFFh |
| 7800h | A000h〜BFFFh |

- 本作では ROM はページ1（4000h〜7FFFh）の2窓（6000h / 6800h）のみで扱う。16KB 単位のデータは、連続する2バンク（偶数バンク→6000h、奇数バンク→6800h）を同時に出して 4000h〜7FFFh に連続配置する。
- 起動時は 4000h〜5FFFh にバンク0が出ている前提でヘッダ・起動処理をバンク0（8KB）に収める。6000h〜7FFFh の初期バンクは不定として扱い、起動処理の冒頭で 6800h に明示的に書き込む。【要検証】

| バンク | 内容 |
|---|---|
| 0 | ROMヘッダ（`AB`、INIT=4010h）、起動処理、スロット検出、ローダー、CPU 切替 |
| 1 | ページ0に置く定数の表（sin 表・逆数表・フォント・スプライト・トロッコの絵・音程表・敵モデル）。起動時に RAM 2800h〜 へ写す |
| 2〜5 | エンジン（RAM 4000h〜BFFFh へ写す。コードと小さな定数） |
| 6〜7 | ステージ1（洞窟）: レール・地形・パレット・スクリプト・字幕・BGM。RAM B400h〜BFFFh へ写す |
| 8〜9 | ステージ2（地底湖） |
| 10〜11 | ステージ3（森） |
| 12〜13 | ステージ4（町） |
| 14〜15 | ステージ5（自宅前）とエンディングの文・BGM |

> 実装メモ: 当初の案（2〜3 エンジン、4〜5 表、6〜7 ステージ…）から、エンジンのコードと表をまとめて 2〜5 に置く形に変えた。
> ステージデータは読み込み先 B400h に合わせて単独でリンクし、先頭 2 バイトに Stage 構造体へのポインタを置く。

#### RAM（内蔵 RAM、スロット3-0、メモリマッパー）

| アドレス | 内容 |
|---|---|
| 0000h〜3FFFh | 起動時は BIOS。初期化後は自前の RAM（マッパーのセグメント 4）: 0038h 割り込み処理、0100h 塗りの展開ブロック、0200h〜19FFh 辺キャッシュ、1A00h〜2763h 地形の表（断面・面の色・飾り・種類）、2800h〜3FFFh 定数の表（ROM のバンク1から起動時に読み込む。約 3.2KB / 6KB）。BIOS が要るステージ読み込みの間だけ BIOS に戻す |
| 4000h〜B3FFh | エンジン（コード・定数）。ゲーム中もページ1は RAM |
| B400h〜BFFFh | 現在のステージのデータ（ROM バンクから読み込む） |
| C000h〜CBFFh | 描画バッファ（64×48＝3072 バイト、1ブロック1バイト） |
| CC00h〜DDFFh | 変数（敵ワーク・当たり判定・リングなど） |
| DE00h〜DFFFh | 多角形の行ごとの左右端 |
| E000h〜E0EFh | 常駐ローダー（ROM バンクからの読み込み） |
| E0F0h〜E0F2h | カートリッジと RAM のスロット ID、BIOS の基本スロット |
| E100h〜EEFFh | レール表（1m ごと、最大 400m） |
| F000h〜F37Fh | スタック |
| F380h〜 | システムワークエリア（使用禁止） |

- ステージデータが大きい場合は、マッパーの空きセグメントに事前コピーし、ページ2の切替（ポート FEh）で参照する方式に拡張する。
- **スロットやバンクを切り替えるコードは、切り替え対象ページの外（ページ3）に置くこと。**切り替え中は `DI` しておく。

#### ローダーの流れ

1. 起動（ROM 上）：自分のスロット番号を検出し、RAM のスロット番号も取得する。
2. ページ3にローダー常駐部をコピーする。
3. ページ2を RAM に切り替え、ROM のバンク2〜3（→6000h/6800h）、続けてバンク4〜5を順にページ1の窓に出してページ2の RAM へ `LDIR` でコピーする。
4. R800 DRAM モードに切り替える。
5. RAM 上のエンジンへジャンプする。
6. ステージ切替時は、常駐ローダーが一時的にページ1を ROM に戻し、該当バンクのステージデータを RAM へコピーする（切替は画面暗転中に行う）。

### 7.4 描画方式

#### 描画パイプライン（1 描画フレームごと）

1. **バッファクリア**：地平線の行を境に、空色・地面色で塗り分ける。
2. **環境ポリゴン**：カメラ変換 → 透視投影 → 奥から順に塗りつぶす（ペインター法）。ポリゴンは平面塗り（フラットシェーディング）の三角形または四角形。
3. **敵・アイテム**：敵の中心座標だけを3D変換し、投影したスケールで「矩形の集まり」を画面に描く（カメラ正対のビルボード方式）。敵は Z の大きい順に描く。
4. **敵弾**：点として投影し、距離に応じて1×1〜3×3ブロックで描く。
5. **HUD**：ライフゲージ、警告文字、スコアをバッファに上書きする。
6. **転送**：バッファ（3072バイト）を SCREEN 3 形式（1536バイト）にパック変換しながら、裏側のパターンジェネレータテーブルへ転送する。
7. **表示切替**：垂直帰線期間に R#4 を書き換え、表と裏を入れ替える（ダブルバッファ）。

#### 敵モデルの形式（矩形の集まり）

```
敵モデル = [矩形, 矩形, ...]
矩形     = (ローカルX, ローカルY, 幅, 高さ, 色, 部位ID)
  ※単位は 1/16m 程度、部位ID は 0=胴 1=頭 2=脚（弱点システム用）
```

- 例：キリン人＝脚（黄・細長）＋胴（黄）＋長い首（黄・細）＋頭（黄）＋槍（黒・細長）
- 例：コウモリ人＝胴（紫）＋頭（紫）＋左右の翼（黒の横長矩形、羽ばたきで高さ変化）
- 当たり判定も同じ矩形群を投影したものを使う。

#### SCREEN 3 の VRAM 形式

- 画面は 32×24 キャラクタ。1キャラクタ（8×8ピクセル）に2×2ブロックが入る。
- ブロック座標 (bx: 0〜63, by: 0〜47) に対応する VRAM 上の位置：
  ```
  cx = bx >> 1
  cy = by >> 1
  pattern = (cy >> 2) * 32 + cx
  addr    = パターンテーブル先頭 + pattern * 8 + (cy & 3) * 2 + (by & 1)
  bx が偶数 → 上位4ビット、奇数 → 下位4ビット
  ```
- ネームテーブルは初期化時に一度だけ「行 r の値＝(r >> 2) * 32 + 列」で埋めて固定する。
- パック変換はルックアップテーブルを使って高速化する。

#### VRAM マップ（案）【要検証】

| アドレス | 内容 | 設定レジスタ |
|---|---|---|
| 0000h〜05FFh | パターンジェネレータ A | R#4 = 00h |
| 0800h〜0DFFh | パターンジェネレータ B | R#4 = 01h |
| 1000h〜12FFh | ネームテーブル | R#2 = 04h |
| 1400h〜147Fh | スプライトアトリビュート | R#5 = 28h、R#11 = 00h |
| 1800h〜1FFFh | スプライトパターン（16×16 ×64 種） | R#6 = 03h |

- 初期化は BIOS `CHGMOD`（005Fh、A=3）で SCREEN 3 にした後、BIOS `WRTVDP`（0047h）で上記レジスタを上書きする。

### 7.5 3D 計算

- 座標は 16 ビット固定小数点（8.8）。ワールド単位 1.0 ＝ 1m。
- sin/cos は 256 分割のテーブル参照。
- 透視投影の割り算は、逆数テーブル（1/Z）との掛け算に置き換える。
- 掛け算は R800 のハードウェア乗算命令を使う。

| 命令 | 動作 | オペコード（参考） |
|---|---|---|
| `MULUB A,r` | A × r → HL（8×8→16ビット） | `ED C1`(B) / `ED C9`(C) / `ED D1`(D) / `ED D9`(E) |
| `MULUW HL,rr` | HL × rr → DE:HL（16×16→32ビット） | `ED C3`(BC) / `ED F3`(SP) |

> 【要検証】使用するアセンブラが R800 命令に未対応の場合は、マクロで `DB` によるオペコード直書きをする。オペコードは実機・openMSX で動作確認すること。

- ニアクリップ面：Z＝0.5m。これより手前は描画しない。敵弾がここを越えたら被弾。
- 見えない環境ポリゴンは、レールが固定であることを利用し、ステージデータ作成時（PC 側ツール）に区間ごとの表示リストとして事前に絞り込んでおく。

### 7.6 フレームレートとタイミング

- 目標：描画 30fps（垂直同期2回に1回描画）、ゲームロジックは描画フレームごとに1回。
- 垂直同期割り込みは BIOS フック `H.TIMI`（FD9Fh）を使う。フックから RAM 上の処理へジャンプし、以下を行う：
  - フレームカウンタ加算
  - 表示ページ切替（描画完了フラグが立っていれば R#4 を書き換え）
  - スプライトアトリビュートの転送
  - サウンドドライバの1ティック処理（60Hz）
- turbo R は VDP ポートアクセスにハードウェアでウェイトが入る。1フレームあたりの VRAM 転送量（約1.6KB）で処理時間に収まるか実測すること。【要検証】

### 7.7 レールとステージスクリプト

#### レールデータ

```
レール区間 = (長さ[m], ヨー角変化[256分割/区間], ピッチ角変化, 速度[m/秒])
```

- カメラはレールに沿って進む。速度は区間ごとに指定（プレイヤーは変更不可）。
- 坂はレールの高さ変化で表し、カメラのピッチを傾ける。

> 実装メモ: 区間は (長さ[m], ヨー角変化, 1m あたりの高さ変化[1/16m], 速度[m/秒×4])。カメラのピッチはレールの傾きの atan（近似）を
> 1 フレームで差の 1/4 ずつ追う。地形はステージの zones で 4m のリング単位に種類を指定する（洞窟・洞窟の出口・地底湖・森・町・自宅前）。
> 屋外の種類（森・町・自宅前）は天井の面を塗らず（色 0 の面は描かない）、先に空と地面を地平線の高さで塗り分ける（5.1）。

#### イベントスクリプト（時間駆動）

```
イベント = (時刻[ティック], コマンド, 引数...)

コマンド例：
  SPAWN     敵ID, X, Y, Z, 行動パターン     ; 敵を配置
  ITEM      MEDKIT, X, Y, Z                 ; 金貨袋を配置
  ATTACKDIR FRONT | BACK | NONE             ; 襲撃方向（警告表示に使用）
  BOSS      ボスID                          ; ボス戦開始（撃破までスクリプト進行を一時停止してよい）
  BGM       曲番号
  PALETTE   ステージパレット番号
  LOAD      次ステージ番号                   ; 暗転してデータロード
  EVENT     CLIFF_FALL | WATERFALL | ARRIVE_HOME
  END
```

- ステージデータは PC 側ツール（Python など）でテキストから変換してバイナリ化する。

> 実装メモ（試作版の命令）: SPAWN / DIR / GO / BOSS / END / TEXT（字幕）/ SPEED / CTRL（操作の可否）/ TURN（自動の振り向き）/
> GRAB（宝箱）/ BGM / FX（効果音・揺れ・画面を白く光らせる）。命令に EV_AT を付けると、時刻の代わりにレール上の位置[m]で実行する
> （カメラがその位置を過ぎたとき。湖に入る・岸に着く・自宅の前で止まるなど地形に結びついた演出に使う）。ステージの切り替えはエンジン側（main.c）が
> バンク 6 → 8 → 10 の順に読み込む。

### 7.8 サウンド（PSG）

- BIOS `WRTPSG`（0093h）または I/O ポート A0h / A1h で直接書き込む。
- チャンネル割り当て：

| ch | 用途 |
|---|---|
| A | BGM メロディ |
| B | BGM ベース |
| C | SE（BGM とは共有しない） |

- ノイズを使う SE（射撃・爆発・体当たり）は ch C で鳴らし、ミキサー（R#7）を SE 側で一時的に切り替える。
- SE の優先度（高い順）：被弾 ＞ 敵撃破 ＞ 警告 ＞ 射撃 ＞ 金貨袋。低い SE は高い SE を上書きしない。

| BGM | 使用場面 |
|---|---|
| 0 | タイトル |
| 1 | 洞窟（緊迫感） |
| 2 | 地底湖（疾走感） |
| 3 | 森（軽快） |
| 4 | 町（にぎやか） |
| 5 | ボス戦 |
| 6 | エンディング（のどか） |
| 7 | ゲームオーバー（短いジングル） |

- サウンドドライバは自作の簡易シーケンサー（音符・長さ・音量の列）で、60Hz ティックで駆動する。

## 9. 実装ルール

1. ROM 上で実行してよいのは起動処理とローダーのみ。ゲーム中の処理はすべて RAM 上で実行する。
2. スロット・バンク切替を行うコードはページ3に置き、切替中は割り込み禁止にする。
3. 毎フレーム実行される処理（描画・転送・3D 計算）では BIOS を呼ばない（VDP・PSG は I/O ポートを直接操作）。起動・初期化・ロード時の BIOS 呼び出しは可。
4. 固定小数点の形式（8.8）をコード全体で統一する。
5. 「【要検証】」項目は、実装時に openMSX で確認した結果を docs/ に記録する。
6. 処理落ちした場合はフレームを飛ばさず、ロジックも遅くなる方式でよい（試作版）。
